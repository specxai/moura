# Changelog

## 0.2.1 — Staged Publishing recovery

- Restore OIDC `npm stage publish` and the human approval boundary in
  [PR #113](https://github.com/specxai/moura/pull/113). Only GitHub Release
  publication stages a candidate; staging success does not mean npm publication.
- v0.2.0 failed at direct `npm publish --tag latest` with E403 / OIDC permission
  denied for this action ([run](https://github.com/specxai/moura/actions/runs/38552023048)).
  Build and package checks succeeded. PR #85 had replaced the working staging
  command with direct publication, which the staging-only Trusted Publisher did
  not authorize. Keep the old v0.2.0 tag and GitHub Release unchanged; do not
  rerun that job or recover the old tag. Prepare v0.2.1 from a new reviewed commit.
- Require release-tag/package version and checked-out commit/event SHA equality
  to keep npm provenance aligned with the packaged source. Manual dispatch on
  main verifies an approved public version only; it cannot stage or publish.
- Retain exact-version npm onboarding verification after human approval,
  triggered manually with `release_version=0.2.1` and `dist_tag=latest`.
- Update package, CLI and official Vitest example versions together. No further
  runtime/API compatibility changes or dependency upgrades from v0.2.0; users
  upgrading from public v0.1.2 must follow the Report CLI v2 migration guidance in
  [the v0.2.1 release notes](docs/release-notes-0.2.1.md).

## 0.2.0 — Report CLI v2

- `moura report [directory] --output <directory>` accepts project-relative and
  absolute destinations. Validate/check arguments and behavior are unchanged.
- **The top-level `moura-report/index.html` is now Quality Overview.** Requirement
  Map moves to `moura-report/moura/index.html`; REQ/Spec HTML moves to
  `moura-report/moura/sources/`. Open the existing top-level path to reach the
  Overview and navigate to the Map. The public API's `outputPath` continues to
  identify the Map; `overviewPath` identifies Overview.
- Overview evaluation/rendering and Japanese-view integrity validation ship in
  the npm package and are shared with Moura's own Quality Site. Node.js >=24
  remains required. No AI/API key, dev tooling, or hosting URL is required.
- Optional Allure results and coverage summary contribute metrics.
- `--allure-report <directory>` and `--coverage-report <directory>` copy existing
  HTML reports and their assets into the portable report and add Overview links.
  External HTML is not generated by Moura; unsafe inputs are rejected.
- `--japanese-views <json>` explicitly configures locally validated translated
  sources. Untranslated titles fall back to English; invalid views are rejected.
- Report output must not exist: existing files and directories, including empty
  directories and previous reports, are rejected without changes. Remove output
  yourself or choose a new path before regeneration. Ownership metadata, hash
  matching, updates and backups are no longer used. Private staging, exclusive
  creation, umask permissions and protected-input/symlink checks remain.

Deferred: configurable external metric input locations.
